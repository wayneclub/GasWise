# GasWise 耗油模型研究與實作選擇

研究日期：2026-10-10，美國洛杉磯時間。
範圍：汽油、柴油、非插電式油電混合車；純電車與充電站不在本階段範圍。

## 研究結論

重新依「目前已取得的輸入」評估，現階段採用 **道路里程的燃油收支模型＋個人完整加油週期校準**。RouteE-Powertrain／FASTSim 是路段資料齊全後的候選，並非目前可以直接套用的模型。冷氣與引擎啟動溫度可參考 EPA MOVES5，公開車型資料校準的物理模型可參考 VT-CPFM；不能只憑整程里程、交通時間、氣溫就唯一決定實際耗油。

現有服務已接入 `distance_fuel_balance_v1` 與 EPA 車型自動基準。選一次車型即可使用綜合 MPG，不需個人紀錄。顯式 MPG／完整週期是可選覆寫；無車型也無覆寫才保留 20 MPG 舊預設並警告。Autonomie、RouteE、FASTSim 尚未接入執行；自動化測試驗證公式與排名行為，尚無實車路線耗油準確度驗證。[車型 API 與驗證](vehicle-fuel-baseline.md)

### 車廠採用證據與現階段選型

**Autonomie 的車廠關聯證據最明確。** 美國能源部指出它由 Argonne 與 General Motors 透過合作研發協議開發，並用於車輛產業；NHTSA 的模型文件記錄主要車廠等機構授權使用。這是合作／使用與模型驗證證據，不能寫成所有車廠「認證」或認證 GasWise 耗油結果。[DOE](https://www.energy.gov/cmei/vehicles/modeling-and-simulation)、[NHTSA 模型文件](https://static.nhtsa.gov/nhtsa/downloads/CAFE/2021-NPRM-LD-2024-2026/Argonne%20Databases/Documentations/ANL_Model_Documentation_NPRM_0421.pdf)

Autonomie 的完整動力系統模型需要大量車輛與駕駛循環輸入。RouteE 需要模型契約指定的路段特徵；VT-CPFM／VT-Micro 需要瞬時功率或速度／加速度。GasWise 現在未取得這些資料，因此不以平均速度、零坡度或預設冷氣負載冒充必要輸入。

EPA 車型 MPG 的測試資料由製造商和 EPA 車輛測試產生，是未來接入車型基準的可靠來源；EPA 車型數值也不能保證特定路線耗油。[EPA 測試資料](https://www.epa.gov/compliance-and-fuel-economy-data/data-cars-used-testing-fuel-economy)

現階段的燃油收支是可稽核的聚合估算，並非新學術模型或車廠認證演算法：

```text
校準 MPG = Σ 完整週期里程 / Σ 完整週期耗油
F(route) = 道路里程 / 校準 MPG（無紀錄時用 user MPG）
ΔF = max(0, F(via station) − F(baseline))
```

不是每次 MPG 的算術平均。週期需同一台車、不重疊、從滿箱到下一次滿箱，計入期間所有補油。API 能驗證格式／正值，無法證明使用者紀錄符合這些條件。加油購買量 `gallons` 與歷史耗油 `consumed_gallons` 是不同概念。

此模型假設候選與基準採同一消耗率；較短路線的負差額沿用現有政策截為零。它不能估計等距路線因塞車或山坡而不同的耗油。交通時間仍用於時間成本，沒有任意塞車倍率。所有排名、價格區間與損益兩平都使用同一耗油量。

請求 `fuel_cycles` 可選，最多 30 筆，例如 `[{"distance_miles":"300","consumed_gallons":"12"}]`。回應新增 `route_fuel_gallons`、`baseline_fuel_gallons`、`fuel_model` 的版本／校準數量／假設，並回傳實際 `mpg_used`。Smart rerank 支援零上游呼叫校準，明示空陣列可清除校準。沒有儲存歷史、車型自動查詢、天氣修正或誤差百分比承諾。

## 一、最適合的研究與演算法

| 模型／理論 | 估計方式 | 需要的關鍵輸入 | 在 GasWise 的用途 |
| --- | --- | --- | --- |
| RouteE-Powertrain | 路段特徵 → 預訓練耗能模型 → 整程加總 | 車型模型、路段里程／速度／坡度；實際特徵依模型契約 | 優先評估的出發前耗油引擎 |
| FASTSim | 驅動循環與車輛動力系統模擬 | 車輛參數、隨時間變化的速度、坡度；附屬負載依版本／模型設定 | 校準與產生 RouteE 訓練資料，不適合拿整程平均速度假裝完整循環 |
| VT-CPFM | 由牽引功率估計瞬間耗油率，再積分 | 速度、加速度、坡度、車重、阻力與車型係數 | 可解釋的物理模型與交叉驗證 |
| VT-Micro | 速度、加速度的非線性迴歸 | 秒級速度／加速度與適用車群係數 | 有 GPS／OBD 軌跡後的比較模型 |
| CMEM | 車輛功率／引擎與運轉狀態模型 | 車群參數、速度軌跡等詳細輸入 | 研究參考，初版整合負擔較大 |
| EPA MOVES5 | 依運轉模式、溫度與冷氣使用修正能耗率 | 運轉模式分布、溫度、濕度、啟動與冷氣資訊 | 天氣與冷氣修正的理論來源，不直接充當某一台車的量測值 |
| Gas Station Problem | 有油箱容量與油價的圖上加油最佳化 | 站點價格、路網耗油、當前油量、容量 | 日後加滿、可達性與多次補給規劃 |

**RouteE 的研究與 Google Maps 有直接關聯。** 國家實驗室官方說明其 RouteE／FASTSim 工具鏈參與 Google Maps 節油路線能力；這不表示 GasWise 目前已取得 Google 的內部耗能估計。[實驗室官方介紹](https://www.nlr.gov/transportation/route-energy-prediction-model)

RouteE 有汽油、柴油與 HEV 模型。官方範例以路段 `distance_mi`、`speed_mph`、`grade_pct` 預測；不同模型需讀取各自特徵與輸出單位契約，不能假定每個模型都接受天氣。它支援預訓練模型及自訂模型。[官方程式與範例](https://github.com/NatLabRockies/routee-powertrain)

FASTSim 是公開的動力系統模擬工具，支援自訂車輛與驅動循環，並作為 RouteE 的底層工具之一。它適合在研究／校準階段重現車輛行駛情境。[官方程式](https://github.com/NatLabRockies/fastsim)、[官方文件](https://natlabrockies.github.io/fastsim/)

## 二、具體公式與限制

### VT-CPFM：功率 → 耗油

Rakha 等人的 2011 年論文發展可用 EPA 市區／高速油耗及公開車輛資料校準的模型。[原論文，DOI 10.1016/j.trd.2011.05.008](https://doi.org/10.1016/j.trd.2011.05.008)

基本形式為：

```text
當 P(t) ≥ 0：q(t) = α0 + α1 × P(t) + α2 × P(t)²
當 P(t) < 0：q(t) = α0

整程耗油 F = ∫ q(t) dt
```

係數必須依車型校準，單位必須一致；不能填入任意通用係數。VT-CPFM 的公開技術資料也指出，功率包含加速、滾動阻力、風阻與坡度，VT-CPFM-2 額外需要檔位資訊。[研究技術資料](https://www.osti.gov/servlets/purl/1509856)

以一般縱向車輛動力學說明功率來源，可寫成下列簡化示意；這不是直接可上線的耗油率公式：

```text
輪上功率 ≈ 速度 × [加速力 + 滾動阻力 + 坡度阻力 + 風阻]
```

相同里程與總時間，可以對應平順行駛或多次停車／急加速。兩者不能以同一個平均速度還原，所以目前的 Maps 總時間不能取代秒級速度軌跡。

油電車有引擎關閉、動力分配與回收行為，不能把上述傳統車的固定怠速形式直接當成通用 HEV 模型；需採用有 HEV 動力系統邏輯的模型，並交代電池狀態假設。

### VT-Micro：速度與加速度迴歸

VT-Micro 使用秒級速度資料，為非線性耗油／排放模型。它適合已有行駛軌跡的情境，不能把一個整程平均速度當作完整輸入。[研究者官方軟體與論文索引](https://sites.google.com/a/vt.edu/hrakha/software)

### MOVES：天氣與冷氣要分開處理

MOVES5 將冷氣影響依運轉模式與溫濕度調整。對已暖機的燃油車，該模型未另加一般運轉溫度修正；啟動能耗的溫度修正與冷氣修正是不同項目。這是模型設計與資料邊界，不代表任何實車暖機後都完全不受氣溫影響。[EPA MOVES5，§2.6、§4](https://nepis.epa.gov/Exe/ZyPURL.cgi?Dockey=P101CTWV.TXT)

GasWise 可參考其結構，估計「沒有冷氣的負載」與「可能開冷氣的額外負載」，但目前沒有冷氣實際狀態或運轉模式分布；不能直接套一個精確修正值。

**基準必須一致。** EPA 的實際道路油耗標示已考慮冷氣、低溫、高速與激烈駕駛測試條件。若採這種 MPG 或使用者日常平均 MPG，不能再毫無基準地疊加完整冷氣／天氣懲罰。應校準相對於原始模型參考條件的變化。[EPA 2025 Automotive Trends Report，2026 年出版](https://www.epa.gov/system/files/documents/2026-02/420r26001.pdf)

### 加油最佳化：Gas Station Problem

Khuller、Malekian、Mestre 的研究把油價、路線與油箱容量放入同一個最佳化問題；固定路線的補給選擇有演算法解法。它主要解決「在哪裡、加多少」，不提供天氣或車型耗油模型，需由另一個模型提供路段耗油。[作者研究頁](https://www.cs.umd.edu/projects/gas/)

以下狀態以本次讀取 `contracts/` 與 `providers/google/routes.py` 為準，不能把「上游可能有」寫成「後端已取得」。

## 四、建議的 GasWise 計算架構

以下是根據研究提出的產品設計，不是宣稱研究已驗證這整套組合。

1. **保留簡單基線。** 路線資料不足時，使用者 MPG 模型仍回傳結果，明示估計依據；不得把缺少速度／坡度補成看似量測的資料。
2. **優先取得路段資料。** 在現有 Maps 回應中驗證可用的路段欄位與身份，再決定坡度來源。只有確認必要特徵齊全後才呼叫 RouteE。
3. **用適用車型的 RouteE 模型估計每段耗油。** 汽油、柴油、HEV 分開；沒有精確車型模型時，使用代表模型並明示映射與不確定性。
4. **對齊模型的參考條件後加入天氣／冷氣。** 未知冷氣狀態用情境或有實測校準的機率處理；不要預設所有駕駛開同樣冷氣。
5. **個人校準。** 使用多次完整加油週期的總里程／加油量校準長期偏差；不能將整箱平均當作某一條短路線的真值。取得 OBD／車載分段資料後才可校準更多細節。
6. **檢查推薦穩定度。** 比較合理的同車、同天氣情境下，推薦站是否保持第一；有足夠獨立驗證資料後才顯示有機率涵義的預測區間。

### 路段與路線耗油

```text
F(route) = Σ 各路段預估耗油 + 尚未包含在路段模型中的啟動／冷氣等負載

ΔF_i = F(起點 → 加油站 i → 目的地) − F(起點 → 目的地)

估計成本 C_i = P_i × Q_i + P_ref × ΔF_i + 時間價值 × Δ時間_i
```

所有耗油統一為 US gallons，時間成本統一為小時 × USD/hour。`P_ref` 是明示的行程燃油價值基準；現有 MVP 採各站價格估算，屬於另一個已明示的近似政策。不能默默在兩種政策間切換。

順路搜尋必須對完整候選與基準路線各自估計耗油，再做差，不能把額外里程當作一條獨立完整駕駛循環。若路段模型已包含怠速、冷氣或暖機，對應項目不再另加。共享天氣與個人校準誤差在候選比較中也應共享，不應獨立抽樣製造額外誤差。

上述固定購買量模型是決策成本近似。若要比較「抵達終點時有相同剩餘油量」，`Q_i` 必須根據抵達加油站前後的耗油調整，並滿足容量／可達性；這與固定買 10 gallons 是不同問題。

### 保留原模型的方法

新增耗油服務可以回傳：

```text
model_id / version
input_quality / missing_inputs
fuel_gallons / estimate_basis
vehicle_mapping / reference_conditions
weather_source / assumptions
scenario_cost_range / ranking_stability
```

不改變油價來源擴充方式；只有資料充分時使用進階模型，缺資料時仍回到明示的 MPG 基線。

## 五、精確度不能只看論文上的百分比

2025 RouteE 驗證報告在對特定車型的冷氣附屬負載等進行校準後，Mazda 3、Honda Accord 的 trip-level NRMSE 分別為 5.95%、6.80%；原報告也提醒測試駕駛條件多樣性有限、可能略有過度擬合。**這不是 GasWise 已達 6% 誤差，也不是預設模型在所有車型／DTLA 短程都保證這個表現。** 本次可取得官方報告的索引摘錄；完整 PDF 抓取不穩定，這些數字只作研究線索。[官方驗證報告](https://docs.nlr.gov/docs/fy25osti/83057.pdf)

GasWise 自己的驗收應包括：

- 耗油 MAE／偏差，以 gallons 表示，特別單列短程。
- 車型、市區／高速、天氣、暖機／冷啟動分組結果。
- 推薦是否選到真正較低成本的站，以及選錯造成多少美元損失。
- 預測區間的實際涵蓋率；沒有驗證前只稱「情境範圍」。
- 與原本距離 ÷ MPG 模型比較，確認進階模型確實改善結果。
- 以不同日期／行程／駕駛或車輛分開訓練、校準與測試；避免相鄰路段隨機切分造成資訊洩漏。

當兩站只差幾角錢，若耗油與油價誤差可能翻轉結果，應顯示「成本接近」。精準的計算不等於精準的輸入。

## 六、工程可行性與下一步

RouteE 主分支目前宣告 Python `>=3.10,<3.14`；GasWise 本地執行環境是 Python 3.14.7。若進入實作，應先用隔離的相容研究環境驗證，不要直接把套件安裝進目前服務。[官方套件設定](https://raw.githubusercontent.com/NatLabRockies/routee-powertrain/main/pyproject.toml)

建議先完成一個資料可行性原型：用同一批 DTLA 候選路線，確認路段特徵與坡度可取得，選定一個汽油車與一個 HEV 的適用模型，輸出原 MPG 基線與 RouteE 預估差異。沒有實際燃料消耗真值時，只能稱為模型比較，不能稱為準確度驗證。

現階段採用：**道路燃油收支 → 可選個人完整加油週期校準 → 基準／經站耗油差额 → 成本與損益兩平**。後續取得路段與車型必要輸入後，再比較 RouteE 與 Autonomie 衍生模型；以實車耗油與推薦成本誤差決定升級，不能只因模型較複雜就替換。
